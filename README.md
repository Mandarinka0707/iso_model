# Лабораторная работа: качество ПО

Статическое веб-приложение для расчёта 25 дифференциальных уравнений и проверки выполнимости плана. Подготовлено для GitHub Pages. Сервер, база данных, npm и сборка не требуются.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub, например `quality-lab`. Для GitHub Free используйте публичный репозиторий.
2. Распакуйте ZIP. Через **Add file → Upload files** загрузите **содержимое** папки проекта в репозиторий. `index.html`, `styles.css`, `model.js`, `visuals.js`, `app.js` и `.nojekyll` должны находиться в корне репозитория. Папки `examples` и `tests` сохраняйте как папки. Если проводник скрывает `.nojekyll`, создайте пустой файл с этим именем через **Add file → Create new file**.
3. Сохраните файлы коммитом в ветку `main`.
4. Откройте **Settings → Pages**.
5. В **Build and deployment → Source** выберите **Deploy from a branch**.
6. Выберите ветку **main**, папку **/(root)** и нажмите **Save**.
7. После публикации нажмите **Visit site** на странице Pages. Адрес проекта обычно выглядит как `https://ВАШ_ЛОГИН.github.io/quality-lab/`. Передайте коллегам адрес, показанный GitHub.

Загружайте распакованные файлы: сам ZIP не является сайтом. После обновления файлы коммитятся в ту же ветку, и GitHub публикует новую версию. Если видна старая версия, обновите страницу с Ctrl+F5.

Официальные инструкции: [публикация из ветки](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [создание сайта и .nojekyll](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## Локальный запуск

Откройте `index.html` в современном браузере. Все пять файлов приложения должны оставаться рядом. Расширения VS Code не требуются. Если нужен локальный HTTP-сервер и установлен Python, из папки проекта выполните `py -m http.server 8000` и откройте `http://localhost:8000`.

Отдельно к ZIP выдается автономный HTML с встроенным оформлением и скриптами. Он подходит для пересылки и локального просмотра; исходники в этом репозитории удобнее редактировать по отдельности.

## Как различать близкие линии

По умолчанию включён режим **По отдельности**: все 25 u показаны в собственных карточках с автоматической шкалой Y. Над каждой кривой указаны начало, конец и Δu. Диапазоны разных карточек различаются и подписаны под графиками.

Для совместного сравнения выберите **Общий график**:

- **Автомасштаб** подбирает Y по выбранным линиям и видимому интервалу времени.
- **Полная шкала 0–1** возвращает нормированный диапазон; значения за его пределами также включаются в шкалу.
- **Задать границы** позволяет ввести точные Y min / Y max. Кривая за ручными границами скрывается только на графике; числовой результат и CSV не обрезаются.
- **t от / t до** увеличивает выбранный участок времени. Границы между узлами вычисляются линейной интерполяцией.
- **Показатель** позволяет рассмотреть один u.
- **Сбросить масштаб** возвращает весь интервал и автошкалу.
- **Показать все линии** восстанавливает 25 показателей после скрытия или фильтрации.

Пример: выберите небольшой участок в конце расчёта и ручные границы Y возле значений интересующих показателей. Для любых параметров сначала смотрите фактические значения в легенде. Масштаб меняет только отображение, а не уравнения и результаты.

## Возможности

- Пять готовых сценариев; изменение начальных значений, порогов и 101 функции связи.
- Шесть факторов с номерами 1, 2, 3, 4, 6, 7 из списка исходного документа.
- Пять лепестковых диаграмм: начало, T/4, T/2, 3T/4, T; экспорт SVG.
- Сохранение / загрузка проекта JSON, совместимость со старыми проектами с тремя факторами.
- Экспорт всех 25 траекторий в CSV.

## Математическая модель

RK4 с фиксированным шагом h и контрольным прогоном h/2. 25 переменных: u1, u7, u8, u9, u10, u11, u34, u35, u36, u37, u38, u39, u40, u41, u42, u43, u44, u46, u47, u48, u50, u51, u52, u53, u57. Индексы не идут подряд.

Связи и аргументы f1…f101 перенесены из `2_laba.docx`. u54 — внешний постоянный параметр: собственного уравнения в исходнике нет. В правых частях присутствуют только Fak1–Fak3. Fak4, Fak6 и Fak7 редактируются, сохраняются и отображаются, но не изменяют u: соответствующих связей исходник не содержит. Курс вводится нормированным числом в [0;1]. Нумерация списка исходника пропускает Fak5.

Коэффициенты, начальные состояния и пороги готовых сценариев — демонстрационные. Похожие значения и линии связаны с похожими параметрами. Новые числовые различия ради картинки не добавляются.

## Проверка

При наличии Node.js выполните из папки проекта:

```text
node tests/verify.cjs
```

Проверяются исходные результаты пяти сценариев, автошкала для близких и постоянных значений, ручные границы, временное окно, 25 SVG-траекторий и пять лепестковых срезов.

Контрольные u1(T) при T=3, h=0,02: **0,502268; 0,592630; 0,494496; 0,566390; 0,932557**. Число достигнутых порогов: **0, 6, 19, 6, 25**. Пятый сценарий — «План выполним».

## Структура

```text
index.html       интерфейс и элементы управления
styles.css       оформление, адаптивность и печать
model.js         уравнения, валидация и решатель
visuals.js       графики, масштаб и лепестковые диаграммы
app.js           действия пользователя, импорт и экспорт
.nojekyll        публикация статических файлов без Jekyll
examples/        пять проектов JSON и таблиц CSV
tests/verify.cjs воспроизводимые проверки без зависимостей
```

Все пути к ресурсам относительные: сайт работает как в корне домена, так и по адресу `/имя-репозитория/`. Внешние библиотеки, шрифты, API-ключи и сетевые запросы для расчётов не используются. Настройки сохраняются локально в браузере; для обмена используйте JSON.
